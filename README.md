# DiskSpace

macOS 13以降のフローティングパネルアプリと、Windows 10/11（x64）の通知領域アプリです。内蔵・マウント中の外付けHDD/SSDの容量を表示します。

## Windows版

**Actions → Build DiskSpace for Windows → Run workflow** でビルドできます。成功した実行の **Artifacts → DiskSpace-Windows-x64** をダウンロードし、ZIPを「すべて展開」した後、**DiskSpace.exe** をダブルクリックしてください。.NETを含む自己完結型のため、利用時の開発ツールや追加ランタイムのインストールは不要です。

Windows版1.2.3は、起動するとネイビーとターコイズのフローティングパネルに残容量・空き割合のゲージを表示します。上部をドラッグして移動でき、「最前面 ON/OFF」で固定を切り替えます。右下や縁をドラッグしてサイズを変更でき、文字とゲージも拡大縮小します。下部の「不透明度」で40〜100%に調整できます（文字やボタンも含むウィンドウ全体の透過）。位置・サイズ・最前面・不透明度の設定は次回起動時に復元します。上部で対象ドライブを選び、「詳細・比較」から容量一覧を開けます。「—」で通知領域へ格納し、通知領域のアイコン（隠れている場合はタスクバーの「∧」）をクリックするとパネルを再表示します。アイコンにマウスを置くと対象ドライブと保存に使える空きを確認できます。Windowsの標準通知領域では、Macのように容量テキストを常時表示する構成にはしていません。一覧で対象切り替え・手動更新・比較情報コピー・終了ができます。×は通知領域へ格納します。

Windows版の「保存に使える空き」は `GetDiskFreeSpaceExW.lpFreeBytesAvailableToCaller`、「ディスク全体の空き」は `lpTotalNumberOfFreeBytes`、「総容量」は `lpTotalNumberOfBytes` です。利用者のクォータ等で値が異なることがあります。Macの「重要なファイル用（推定）」と同じ指標ではありません。エクスプローラーと比べるときは同じドライブのプロパティの**バイト値**で比較してください。Windows版1.2.3からWindowsと同じ1024進の単位を使用し、小数第2位まで四捨五入して表示します（1 GB = 1,073,741,824バイト）。画像の394,110,242,816バイトは367.04 GB、998,976,253,952バイトは930.37 GBと表示します。Windowsプロパティより細かい桁まで表示します。小さい容量にはMB等を使います。測定タイミングやクォータにより容量自体が異なる場合は、比較情報のバイト値で確認できます。

固定・リムーバブルの準備済みドライブを列挙し、30秒ごと・接続/取り外し時に更新します。選択対象を取り外すと起動ドライブへ戻ります。ドライブ文字のないフォルダマウント、ネットワーク、光学ドライブは今回の対象外です。

開発には.NET SDK 8とWindowsを使用します（Visual Studio 2022でもcsprojを開けます）。

```powershell
dotnet run --project Windows/DiskSpace.Tests -c Release
dotnet run --project Windows/DiskSpace
dotnet publish Windows/DiskSpace -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -o build/windows-package
```

Actionsでは容量変換・Windows表示・ゲージ比率などの8件のテストに加え、配布exeで実際の起動ドライブ取得、ウィンドウ生成・表示、クリップボードの読み書きをスモークテストします。対話的な画面操作・実機の外付け接続/取り外しは別途確認が必要です。署名していないためSmartScreenで止められる場合があります。詳細は [Windowsの日本語説明](Windows/README-ja.txt) を参照してください。

Windows版1.2.3は上記の自動検証に成功しています。[検証記録](Windows/TESTING.md)で確認済み・未確認の範囲を確認できます。

## macOS版を入手して使う

[macOS版のリリース](https://github.com/atstti/codexssd/releases/tag/macos-v1.2.0)から、Apple Siliconなら `DiskSpace-macOS-arm64.dmg`、Intel Macなら `DiskSpace-macOS-x86_64.dmg` をダウンロードします。「このMacについて」の「チップ」または「プロセッサ」で機種を確認できます。

1. DMGを開き、**DiskSpace.app** を **Applications** にドラッグします。更新時は既存のDiskSpaceを終了してから置き換えます。
2. アプリを開くとフローティングパネルが表示されます。上部のタイトルバーをドラッグすると移動でき、端や角をドラッグするとサイズを変えられます。「最前面」で固定を切り替え、「不透明度」で40〜100%に調整できます。
3. ドライブを選ぶと「重要なファイル用（推定）」が大きく表示されます。下の一覧で「現在の空き」などを確認でき、「比較情報をコピー」でバイト値と測定情報を取得できます。
4. パネルを閉じた後は、Dockのアイコンをクリックするか「アプリケーション」からDiskSpaceを開くと再表示できます。完全に終了するには ⌘Q を押します。

Appleの公証は行っていません（アドホック署名）。Gatekeeperで起動が止まる場合は、配布元を確認したうえで「システム設定 → プライバシーとセキュリティ → このまま開く」を選んでください。

## Xcodeで起動・開発

1. MacにXcode 15以降をインストールし、初回起動を完了します。
2. このリポジトリの **Package.swift** をXcodeで開きます。
3. `DiskSpace` スキームと実行先 `My Mac` を選択し、Run（⌘R）します。フローティングパネルが開きます。
4. Test（⌘U）で容量変換のテストを実行します。

コマンドラインから検証・アプリ化する場合：

```sh
cd <このリポジトリ>
swift test
bash scripts/build-app.sh
```

出力は `build/DiskSpace.app` と `build/DiskSpace-macOS.zip` です。通常利用は作成済みの **DiskSpace.appをダブルクリック**してください。ビルドは実行したMacのアーキテクチャ向けです。

## どの容量を測っているか

| 表示 | 取得方法・意味 |
| --- | --- |
| 総容量 | `statfs.f_blocks × f_bsize` |
| 現在の空き | `statfs.f_bavail × f_bsize`。dfのAvailableと比較する値 |
| 重要なファイル用（推定） | Foundationの `volumeAvailableCapacityForImportantUsage`。OSによる推定値。パネル上部に表示 |

内部はバイト単位、表示は十進（1 GB = 1,000,000,000バイト）で小数第2位です。0は `0.00 GB`、取得失敗は `取得できません` と表示します。固定値の加算やFinderに合わせる補正はしません。推定値はFinderの「空き領域」や「パージ可能」そのものではなく、その差をパージ可能容量とも断定しません。

起動ディスクは `/` の利用者向け名称で1回だけ表示し、ユーザーデータを書き込む `/System/Volumes/Data` を測定します（パスがなければ `/`）。補助マウント `/System/*`、`/private/*`、Preboot・Recovery・VM等は除きます。その他はローカルで表示可能なAPFS/HFS+/exFAT/FAT/NTFSのマウントを列挙し、同じデバイスの重複は除きます。ネットワークドライブ等は対象外です。APFSコンテナ内では容量を共有するため、各行の総容量・空きを足し合わせないでください。

30秒ごと、およびマウント・取り外し・名称変更・スリープ復帰・画面を開いた際に更新します。取得はバックグラウンドで行います。選択したドライブがなくなった場合は起動ディスクへ戻ります。

## Finderとの比較手順

1. アプリで対象ボリュームを確認し「手動更新」→「比較情報をコピー」を押し、テキストエディタへ貼り付けます。測定パス、UTCの測定時刻、各容量の未丸めバイト値を保存できます。
2. Finderの「移動 → コンピュータ」で**同じボリューム**を選び「情報を見る」（⌘I）を開きます。起動ディスクの場合、比較情報の測定パスはDataボリュームになります。
3. Finderの空き領域、括弧内のパージ可能容量、確認時刻を別途記録します。大きなファイル操作を止め、なるべく同時に比較してください。
4. 必要ならターミナルで `df -k /System/Volumes/Data`（外付けは比較情報のパスを引用符で囲む）を実行します。Availableに1,024を掛けてアプリの「現在の空き」のバイト値と比較します。測定間の書き込みで差が出る場合があります。

観測例：`16,242,320 × 1,024 = 16,632,135,680` バイト → **16.63 GB**。このときFinderのパージ可能が155.7 MBなら加算結果は約16.79 GBですが、これは一例であり、毎回成り立つ式ではありません。FinderとAPIの更新タイミング・推定・丸め等が異なるため、一致を保証しません。

## 検証状況

GitHub ActionsのApple Silicon／Intelランナーで `swift test`、パネルの起動・サイズ変更・閉じる操作・再表示のスモークテスト、リリースビルド、アドホック署名検証、DMGの整合性検証とマウントを実行します。手動のドラッグ操作・実ドライブの接続取り外し・Finder比較は別途確認が必要です。結果は[リリースノート](https://github.com/atstti/codexssd/releases/tag/macos-v1.2.0)に記載しています。

テストには上記の観測値、0と取得失敗の区別、十進単位、整数オーバーフローを含めています。Macでアプリを開いた後、パネル表示・対象切り替え・コピー内容・30秒更新・外付け取り外し時の起動ディスク復帰を確認してください。
